Day 2

MAKE IT YOURS

Turn the boring page into your page.

A page is just tags

<html>
  <body>
    <h1>Hello!</h1>
    <p>This is my page.</p>
  </body>
</html>

Tags open <h1> and close </h1>. That's most of it.

Steal a whole page (legally!)

  • Go to W3Schools → "Try it Yourself" on any example.
  • Select the whole document — <html> and <body> included.
  • Paste it into the PASTE slot in your sketch.

You own the whole page, so a full document is fine — no doubling of <html>/<body>.

Cool tags to try

Headings & text

  • <h1> … <h6>
  • <p> <b> <i>

Colors

  • style="color:magenta"
  • style="background:#111"

Images

  • <img src="...">

Links & buttons

  • <a href="...">
  • <button>Click</button>

Lists

  • <ul><li>item</li>

A little CSS

  • <style> h1{color:lime} </style>

Flash & watch it change

Upload again, refresh 192.168.4.1 — your page is live.

Change one thing, upload, refresh. Repeat until it's yours.

SECRETS & COMMUNICATION

Hide a flag. Leave a trail only a hacker can follow.

Servers also send headers

When the server answers, it sends the page and hidden notes called headers.

CLIENTasks
→
SERVERreplies with
page + headers

You see headers in the Network tab — click a request, read "Response Headers".

A header that points somewhere

X-Access: L3RyZWFzdXJl
  • That value is base64 — a simple scramble, not a password.
  • Decode it → a secret path like /treasure.
  • Decode with the base64 tool, or the browser console: atob("L3RyZWFzdXJl")

Set your secretPath

  • In the edit zone, set secretPath = "/yourpath".
  • The server broadcasts it for you in the X-Access header (base64).
  • You never write the header — the board does it automatically.

Hide your flag — twice

  • Pick a flag, e.g. PURPLE-TIGER-9.
  • Once hidden in your page source (choose a trick → next slide).
  • Once as the answer — set flag = "PURPLE-TIGER-9" in the edit zone.

Attackers find the hidden one, then type it into your secret page.

Where to hide a flag

Grouped by the DevTools skill it teaches.

View Source

  • <!-- FLAG -->
  • <meta name="x" content="FLAG">
  • <script>let k="FLAG"</script>
  • <noscript>FLAG</noscript>
  • <template>FLAG</template>

Network tab

  • a custom response header (the path pointer)
  • a Set-Cookie clue

Console tab

  • <script>console.log("FLAG")</script>

Elements / DOM

  • hidden / display:none
  • off-screen position:absolute;left:-9999px
  • opacity:0 / font-size:0
  • data-secret="FLAG" · title="FLAG"
  • <input placeholder="FLAG">
  • text written backwards · SVG <title>/<desc>

Application tab

  • a cookie
  • localStorage.setItem("k","FLAG")

Decode step (required)

  • base64 — already used on the header path

Not on the list: alt (only shows if the image fails) and white-on-white (too easy).

Your secret page

  • Opening secretPath shows a submit box.
  • Right flag → YOU PWNED [you] & you're marked breached.
  • Wrong flag → ACCESS DENIED.
